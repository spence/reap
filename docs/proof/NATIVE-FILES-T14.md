# Owned native Files preview and shared reports

## Scope and behavior

The foreground declaration command and internal native preview use one assessment engine.
Its structured report separates discovery, planned, blocked, completed, and unknown-residual units.
Failed or discarded diagnostic output cannot remove safety inputs or change those counters.
Only successful mutations count as completed units. Unproven residual effects remain explicit.

Internal read-only Files jobs use the existing resolver, bulk grants, physical slots, and durable journal.
The preview binds caller, namespace, configuration, governed roots, state inputs, and native physical evidence.
Proven absent roots differ from existing non-directories. Changed evidence refuses assessment.
Descriptor-relative traversal does not follow child symlinks or cross an ungranted device.
Unsafe inputs, object replacement, incomplete enumeration, and exhausted allocation budgets refuse complete coverage.
Unknown Git or activity evidence remains incomplete; preview starts no ungranted helpers.
Targets and the first-seen cache remain unchanged.

Deterministic task validation and combined-packet capacity failures refuse only the affected job before a new launch.
Journal and uncertain-ownership failures remain service failures.
Restart and replay retain the original operation, source evidence, live child, and resource reservation.
A lost result does not permit a duplicate launch or successful terminal result.
